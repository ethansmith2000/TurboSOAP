# FastSOAP candidate — 2026-10-19

The user requested a separate implementation that prioritizes low overhead and
tests loss in training rather than treating reference error as the objective.
[fast_soap.py](fast_soap.py) implements that candidate without modifying the
qualified J1 path or the running native-precision sparse-refresh trial195.
This is candidate development, not a measured speed or learning result.

## Execution policy

```python
import torch
from fast_soap import FastSOAP

# Set once, outside the training loop. Optimizer steps run outside autocast.
torch.set_float32_matmul_precision("high")
optimizer = FastSOAP(
    matrix_parameters,  # dense 2D FP32 parameters; other parameters use Adam
    lr=learning_rate,
    shampoo_beta=0.99,  # explicitly match the experiment recipe
    precondition_frequency=20,
    hard_reset_interval=200,
)
```

The constructor checks the caller's precision setting without changing it.
The caller must retain that setting. There are no precision setters, context
managers, reference comparisons, scalar extractions or acceptance controllers
inside the warm kernel. Setup validation is outside the hot path.

Covariance, bases and both moments remain FP32. Basis-space covariance products,
Gram products, ordinary projections, covariance accumulation, first-moment
transport and scheduled QR inherit the caller's global `high` policy. FP32
storage does not imply full IEEE FP32 multiplication under that policy.

The candidate displacement and two residual corrections use BF16 operands and
direct FP32 output on CUDA:

```python
torch.mm(left.bfloat16(), right.bfloat16(), out_dtype=torch.float32)
```

The installed PyTorch is 2.11.0+cu128 and documents this CUDA operation locally.
Compared with `(left.bfloat16() @ right.bfloat16()).float()`, this avoids a BF16
result followed by conversion to FP32, and removes the intermediate output
rounding. It retains six operand conversions across those three products.
Whether those conversions become separate kernels depends on generated code.
No lower-precision persistent basis cache is introduced.

## Warm arithmetic and compilation

The entire warm refresh is one `torch.compile(fullgraph=True, dynamic=False)`
function, allowing pointwise work and operand conversions to fuse across the
previous prefix/retraction boundary. It still contains seven dense products
per factor; one compiled graph does not mean one GPU kernel.

The generator uses these relative units:

```python
b = q.T @ covariance @ q
b = 0.5 * (b + b.T)
d = b.diagonal()
scale = d.abs().amax().clamp_min(1e-30)
gap = (d[:, None] - d[None, :]) / scale
rotation = -0.5 * (b / scale) * gap / (gap.square() + 0.01**2)
```

It then caps `rotation.norm() / sqrt(2)` at 0.5, forms the displacement and
applies two residual corrections. The normalized generator is algebraically
the J1 damped Jacobi step away from numerical floors, but floating-point
evaluation differs. The trace reduction and covariance-normalization pass
are removed. Explicit antisymmetrization of the already skew generator is
removed. `amax` and the rotation norm remain algorithmic reductions.

This assumes finite PSD covariance at a representable scale. Zero covariance
is handled. Extreme scales can differ from the old trace/denominator floors;
the unnormalized covariance products can overflow before relative scaling.
Equal basis-space diagonal entries still give zero rotation even with
off-diagonal covariance. These are numerical/model limits, not diagnostics
to run at every refresh.

Two correction passes remain fixed for this first candidate. Reducing to one
is a later isolated ablation, not an assumed safe change. Fresh casts of the
updated basis in each pass are necessary for its intended arithmetic.

## Optimizer semantics and scope

`FastSOAP` shares `ResearchSOAP.step`, covariance accumulation, initialization,
QR sorting, first-moment transport and variance handling. The cold first call
initializes covariance/bases and does not update matrix parameters. Ordinary
updates precede covariance accumulation and refresh. Warm refresh carries V;
QR repair permutes V. The first moment is transported through physical space
at caller precision, replacing the old `highest` transport policy.

The complete optimizer step remains eager. This change targets the warm
function, precision switches and result-conversion traffic; it does not claim
to remove ordinary-step Python dispatch or all inherited state metadata.
Per-shape compilation and cold eigendecomposition must be charged separately
from steady-state measurements. `compile_warm=False` provides an explicit
eager audit path; there is no automatic fallback on compilation failure.
