## Frozen comparison

Bundle: `/workspace/optimizer_replay_results/soap_bf16_learning_20261026_v1`.
Runner: `benchmarks/bf16_learning_compare.py`, using the extended screen harness.
Optimizer source and mathematics are unchanged from the successful screen.

Five fresh subprocesses run sequentially on one lifetime GPU claim:

1. `qr10`: stock SOAP QR10, original ResearchSOAP implementation, primary reference.
2. `original`: existing FP32-state FastSOAP, warm10 with QR50 repair.
3. `compiled_fp32`: batched/compiled candidate, FP32 state, BF16 matrix arithmetic.
4. `bf16`: same candidate, BF16 M/V/C/Q.
5. `bf16_fp32_basis`: same candidate, BF16 M/V/C and FP32 Q.

All use model seed 204, stock matrix betas (.95,.95), covariance .95, epsilon
1e-8, peak matrix LR .0015, decay .05, global clipping 1, original auxiliary
AdamW (.9,.999) with peak LR .0006 and the original decay grouping. The schedule
retains the full **10,000-call horizon**, 200-call linear warmup, minimum ratio
.1. It is not compressed into 2,000 calls. Every arm begins from scratch; no
checkpoint resume, LR sweep, adaptive repair or policy switch is allowed.

Same 109,396,992-parameter Transformer, width768/depth12/heads12, FF hidden1536,
fused QKV/SwiGLU, tied embeddings, RoPE/QK norm, no dropout/bias. Eager model
forward/backward under BF16 autocast, compiled FP32 token CE. FP32 master weights.
Physical batch8, accumulation4, global32, token blocks1024 with1023 targets.
Use the first64,000 frozen training rows from the completed OWT restart cohort,
with identical row order in all arms. Training targets: 65,472,000 per arm,
327,360,000 total. The first matrix call initializes state; auxiliary AdamW
still updates, giving1,999 matrix updates per arm.

No new dataset download or tokenization. Symlink the same frozen train.npy and
validation.npy and verify hashes. Each startup must reproduce the successful
screen's initial parameter/gradient hashes, repeat the initial backward exactly,
and match the completed full-panel baseline's initial CE. Validation uses all
1,024 frozen rows, unlike the screen's128-row panel.

Managed program `soap-bf16-learning`, no autostart/restart/retries. Admission
through `/workspace/bin/gpu-claim`, wait at most300s, one GPU, arms sequential.
30-minute wall limit per arm, two-hour campaign limit plus bounded admission,

Only source, hashes, configuration and scalar/log evidence are saved. No model
weights or optimizer tensors/checkpoints. Fresh source snapshot and input hashes

On completion, the parent audits event/observation counts, initial matching,
evaluation preservation and graph counts, then writes `comparison.json` and

`reports/bf16_learning_20261026/`. These outputs distinguish measurement completion
from the numerical qualification flags. Supervisor exit status is authoritative
for process completion; an EXITED label alone also occurs for failures.
